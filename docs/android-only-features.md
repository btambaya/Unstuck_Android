# Android-only features (reverse parity: Android → web)

**Companion to `audit-web-parity-gaps.md`** — that doc tracks web features Android lacks; this one tracks the reverse: capabilities the Android app has that the **web** app does not. Re-scanned 2026-06-06 via the `android-only-features-scan` workflow (8 agents, one per Android-rich area, each checking the web repo for the equivalent).

## Rollup

- **26 Android-only capabilities** — 16 platform-inherent · 5 feature-level · 5 Android-UI-for-shared-backend.
- **11 are web-port candidates** (feature-level or shared-backend with user value) — the rest are OS-bound (notifications, exact alarms, foreground service, home-screen widget, permission prompts) and can't meaningfully port.

## ⭐ Web-port candidates (Android leads — consider for web)

These exist on Android but not web, and either the backend is already shared or they're portable product concepts:

- **Reminder lead-time setting ("Remind me before tasks": Off / 5 / 10 / 15 min)**  _(feature-level)_
  - web today: none — Settings > Notifications (components/settings/notifications-settings.tsx) is only an on/off push toggle; no lead-time control anywhere.
  - The CONTROL is a portable product concept and would belong on web if/when web gets any reminder mechanism (e.g. a server reminder cron). Today web fires no pre-task reminder so the setting has nothing to drive, but it's a feature-level gap, not OS-bound. Note Android stores it device-local (SharedPreferences), not synced — so even on Android it isn't a cross-device pref yet.
  - android: `ui/settings/SettingsScreen.kt:127 SegRow('Remind me before tasks'), SettingsStore.reminderLeadMin (default 10), persisted device-local`
- **Notification 'level' preset — Calm / Balanced / Coach (gates start-now nudge, drift follow-up, paused check-in, in-app nudges)**  _(feature-level)_
  - web today: none — no notification-intensity preset on web; web has only a global on/off and a separate 'Show gentle nudges' toggle under Focus.
  - A genuine product idea web could mirror at least partially: Coach-style 'didn't start on time' nudges and paused check-in opt-out. The paused-checkin enable/mute already lives server-side in notification_preferences (paused_checkin_enabled/muted_until, read by send-paused-checkin), so a Balanced/Coach toggle for that piece is shared-backend-ready; the start-now/drift gating is moot on web until web fires those reminders.
  - android: `NotificationLevel.kt (CALM/BALANCED/COACH with atStart/drifted/pausedCheckin flags), SettingsScreen.kt:131 SegRow('Notifications'), SettingsStore.notificationLevel`
- **Per-task reminder override (Default / Off / 5 / 10 / 15 min per task, set in the new-task sheet)**  _(feature-level)_
  - web today: none — web task create modal, task detail pane, and schedule-task modal have zero reminder fields.
  - Per-task reminder lead is a portable product concept, but on Android it's stored device-local (not in the synced task row), so it isn't a cross-device feature even there — porting to web would arguably want to promote it to a real synced task field first. Gated behind the same 'web has no reminder firing' limitation.
  - android: `ui/tasks/NewTaskSheet.kt:175-182 'Remind me' chips, AppViewModel.setReminderOverride, SettingsStore.reminderOverride/setReminderOverride (device-local key reminder.override.<taskId>)`
- **Paused-too-long check-in nudge ('Did you step away?') fired ~14 min after pausing, even with the app closed**  _(platform-inherent)_
  - web today: none — web has an in-page overrun/check-in state (lib/use-focus-timer deriveState 'overrun', state-label 'OVERRUN · GENTLE CHECK-IN', at most a Web-Audio bell) and a resume-support screen, but all only render while the /focus tab is open; there is no scheduled local notification when paused and away
  - This is a genuine product feature (a behavioral nudge to re-engage after stepping away), not just a UI shell. The server-side allowance gate (notifications.pausedCheckin: daily cap + preference + self-mute) is already shared backend. Web has the notification-level preference plumbing and a service worker; it could deliver a comparable 'still paused — resume?' nudge while the tab is backgrounded (e.g. via SW + a timer or a server push), giving the away-from-screen re-engagement that the in-page overrun banner can't provide. The exact 14-min closed-app timing is platform-inherent, but the feature itself is a reasonable web port candidate.
  - android: `surface/PausedCheckinScheduler.kt + PausedCheckinWorker (WorkManager OneTimeWork, DELAY_MIN=14, re-checks server pausedCheckin() allowance and posts NotificationRenderer.postPausedCheckin); armed on ACTION_PAUSE in NotificationActionReceiver`
- **Move a collection item to a real task (promotion), with a shared-list "Just me vs Keep everyone in the loop" chooser**  _(shared backend, Android-only UI)_
  - web today: none — use-collections.ts has no moveItemToTask/promote function; collection-detail.tsx and collection-item-row.tsx expose only done/pin/edit/remove; no AddTask action; the backend RPC collection_set_item_promotion and tasks.source_collection_id columns (migration 025) exist but web never calls them

- **By-time ("due by") picker when keeping everyone in the loop, scheduling the resulting task onto the calendar**  _(feature-level)_
  - web today: none — web has no concept of a collection-item due time; CollectionItem type has no dueAt; backend tasks.due_at column (migration 025) is unused by web
  - Promotes with an ISO by-time, guards against being born overdue (rolls to tomorrow if the chosen time already passed), and schedules the new task so it appears on the calendar. The web TimePickerDialog is platform-native but the underlying feature (pick a by-time on promotion) is fully portable via the existing due_at column.

- **Notifications-off warning banner on the home/Today surface**  _(feature-level)_
  - web today: Web knows the permission state — pushPermission() in lib/firebase/web-push.ts returns Notification.permission, and components/settings/notifications-settings.tsx renders a 'Blocked in your browser settings…' sub-line when permission==='denied'. But this is buried in Settings as a passive toggle; the dashboard/Today surface (app/(product)/dashboard/page.tsx) has NO proactive banner. No equivalent on the home surface.
  - Android proactively surfaces a silent-failure case (reminders fire and log in-app but the OS suppresses delivery) right where the user lives, with a one-tap deep-link to fix it. The browser Notification permission API is the direct analogue of areNotificationsEnabled(), so this is web-portable. Web has the extra wrinkle that there is no OS-settings deep link — the banner should route to /settings (the push toggle) and, for the 'denied' state, explain that it must be re-allowed in the browser's site settings.
  - android: `app/src/main/kotlin/tech/csalliance/unstuck/ui/today/TodayScreen.kt lines 90-97 (notifsEnabled re-checked via NotificationManagerCompat.areNotificationsEnabled() on every Lifecycle ON_RESUME) and lines 179-201 (amber banner item: 'Notifications are off' / 'Reminders won't reach your phone. ---

**Net:** Android meaningfully leads web in **11** places. The 5 shared-backend ones (move-to-task accountability, the by-time picker, promotion status chips, completion→collection notify, archive UI, the feedback composer) are the cheapest to reach web parity since the Supabase tables/functions already exist — only the web UI is missing. The 5 feature-level ones (reminder lead-time, Calm/Balanced/Coach level, per-task reminder override, paused check-in, notifications-off banner) are portable product ideas, several gated behind web first gaining any client-side/cron reminder mechanism.
